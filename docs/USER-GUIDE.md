# 使用说明

在 Codex Desktop 的 Chat 模式选中助手回答，点击「提问」。引用保留原文；Enter 发送，Shift+Enter 换行，中文输入法行为延续原版本。每个旁注拥有独立 Thread，可停止生成、拖动、折叠和关闭。关闭后历史仍保留。

按 Ctrl+Alt+H、旁注的「历史」按钮，或开始菜单 Annotation History 打开历史窗口。搜索支持标题、原文、问题与回答，停顿 300ms 后查询；可选择账号、创建日期和归档状态，每页 50 条。单击记录可改标题，再点「打开旁注」。回收站可恢复软删除记录。永久清空需要确认，只作用于当前筛选账号，不会影响其他账号；旧备份和 Codex 自身的线程历史单独管理。

恢复不会重发问题。下一次发送会核对当前账号并恢复原 Thread。账号不匹配会阻止发送；Thread 不存在时会出现「新 Thread 恢复」，确认后下次发送将使用引用和本地已完成问答建立新的上下文。失败、取消和因退出中断的 AI 文字不会伪装成完整历史。

「模型与用量」读取当前 App Server 的模型目录。可设为当前账号的默认模型或用于单个旁注；生成过程中无法切换。不可用模型会要求重新选择，不会静默换用另一模型。用量只显示协议实际提供的数据。

回答中的代码可展开、横向滚动、原样复制；长代码默认折叠。复制问题/回答保留原始 Markdown。HTTP(S) 链接由系统浏览器打开；HTML、远程图片与可执行链接不会渲染。

数据位于 `%LOCALAPPDATA%\ContextNotesNative\data\history.db`，包含个人对话，请妥善保护。退出时自动备份为 `history.db.backup.db`，历史窗口也可导出一致性备份。出现「历史暂未保存」时保持程序运行，恢复磁盘空间或数据目录权限；后台会重试，关键状态未保存时会阻止新请求。

恢复备份：先停止 Companion 和 Watcher；将原 history.db、history.db-wal、history.db-shm 一起移至独立安全目录，保留以便回退；将备份复制为 history.db，确认目标不存在旧 WAL/SHM，再启动。不要只覆盖数据库文件而留下另一版本的 WAL。数据库版本过新或完整性检查失败时原文件会保留，不会自动清空。
